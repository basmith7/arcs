# Changelog

Moved from AGENTS.md on 2026-10-08. Newest first.

- **v0.18.2** no app change: the image runs on Node 24 (`node:24-alpine`), and the v0.16.3 CA workaround is gone now that nodejs/node#66871 shipped; `engines`, `@types/node` and the esbuild targets follow
- **v0.18.1** no app change: the image is built by the shared `basmith7/workflows` build (`.github/workflows/build.yml`), so it carries its commit and version labels (`deploy-app status arcs` shows them), and it deploys with tower-deploy's `deploy-now` (`.tower-deploy`), which also syncs `docker-compose.prod.yml` to Tower. `scripts/deploy-now.sh` is gone
- **v0.18.0** **End turn** sends itself after two minutes (the countdown is on the button) or when you leave the page, and its panel shows which of your moves Start over takes back and which are locked in behind a roll, draw or peek. A move that can't be undone (a card draw, a look at a hand) now asks **Go ahead** first; the battle window's Roll and Reroll say "Can't be undone" on the button instead of asking. The setting is now Settings > Board > Confirm moves (`confirmMoves`; a stored `confirmEndTurn` is ignored, so it reads On again)
- **v0.17.0** online, the move that ends your turn waits on your device for **End turn**, with **Undo last move** and **Start over** (back through your own moves this turn, stopping at a dice roll, draw or peek, by the same `takeBackBlock` rule as Undo; Settings > Board > Confirm end of turn, on by default). Private per-seat **Notes** under the log, saved on the server (`seat_note`, `GET`/`POST /games/:id/note`) so a plan follows you between devices. On desktop the log is always a column (the pin toggle and `logPinned` setting are gone, and so is the desktop's turn feed over the map)
- **v0.16.3** the runtime image makes Node trust the patched OS CA store (`apk upgrade ca-certificates-bundle`, `NODE_OPTIONS=--use-openssl-ca`) because Node's bundled roots still trust the eMudhra intermediates revoked as compromised on 2026-10-18/19 (#25, #26); drop it once the Node base image ships nodejs/node#66871
- **v0.16.2** every catch-up draft and the checker's verdict is kept in a new `catchup_attempt` table (server-side only, not cleared at game end), so a seat's "bullets only" can be read back on Tower; `npm run catchup-try -- <game> <faction>` re-runs a seat's story and prints the drafts
- **v0.16.1** the stall reminder also tracks games already waiting when the server starts (`Notifier.watchStalls`); before, only a game that moved after the deploy was tracked
- **v0.16.0** a **daily stall reminder**: a game waiting on a human seat with no move for 24 h pings that seat on Discord at 16:30 America/Phoenix (sent within the hour after; `REMINDER_TIME`/`REMINDER_TZ`, `off` disables), once a day up to 7 per stall, skipping pings-off and bot seats. Held turn pings now live in SQLite (`pending_ping`, one 30 s sweep), so a deploy no longer drops them. Removed upstream leftovers: the Cloudflare/Pages `Deploy` workflow and the per-game webhook (`game.webhook_url` dropped by migration, lobby field gone). The toolbar fits the window down to 1200 px and wraps below
- **v0.15.0** a **stats page** (`#/me/stats`, from My Games; `GET /me/stats`, own stats only, worked out from claimed games: record, power and place per table size, by leader and colour, history; hotseat games listed but not counted). Final standings break power ties by initiative order like the engine's winner pick (engine `standings`/`turnOrder`; the game-over screen could list a non-winner first on a tie). Online games get a server-picked seed (#18: "trust the table" otherwise, spec `2026-10-14-hidden-info-design.md`). A signed-in player holding another seat in the game can unlock a seat locked to the wrong account (#23). System Back closes an open dialog (#17). The catch-up card folds to its title after your opening play, and a late story no longer shifts it (#22). Cookie POSTs refuse foreign origins and non-JSON (#24), presence and lock state follow seat changes, Sit here/Add games failures show. Session polls no longer double-apply (#16)
- **v0.14.1** Discord login turned on in production (the Pikachu app). Signing in from a seat you're playing locks it on the way back (`arcs.signin.sitOnReturn`); opening a link while already signed in still asks "Sit here". A signed-out player in a seat gets a one-time sign-in bar (`SignInNudge`). Fixed: Settings link-buttons now use the small button type, a button in a settings row widens its column (Unlink spilled out and scrolled the dialog sideways), and the game screen clips to one window (the hand cards' hover strips made the page scroll onto a black band)
- **v0.14.0** optional Discord login (arcs/T-3) — off on prod until `DISCORD_CLIENT_ID`/`DISCORD_CLIENT_SECRET` are in Tower's arcs `.env` (the compose already passes them); a seat locked to an account is refused by `/claim` (Who are you?) and `/catchup` to anyone else, and "Sit here" is `POST /games/:id/sit`
- **v0.13.0** a **Scoreboard** (header dialog on desktop, fifth tab on phone; engine `gameFacts`, the "if the chapter ended now" line is the real `ambition/score` read through `buildChapterReport`, now in the engine) and a per-seat **turn catch-up** card: code-picked heads-ups (`seatFacts`, five kinds) shown at once, plus a DeepSeek story written on the hand-off (`catchup.ts`: `deepseek-v4-pro` writes, `deepseek-flash` checks, one rewrite, else bullets only), stored in a `catchup` table keyed by where the turn began (`seatTurn`), pushed down the seat's socket, `GET /games/:id/catchup`. Needs `DEEPSEEK_API_KEY` in the compose env; without it the card shows bullets only. `npm run recap -- <game> --seat <faction>` prints a seat's heads-ups
- **v0.12.0** a game link with no seat token (and none stashed in this browser) asks "Who are you?" — the human seats by name, or Just watching; a pick calls `POST /games/:id/claim {faction}` for that seat's token (deliberately trusting: anyone with the game link can take a human seat, never a bot's) and joins it before dropping the watching session; also fleets sit by the gate ring and hovering a piece lights its system
- **v0.11.2** your hand can be read on other players' turns in a joined game (it sat inside `Watching`'s `inert`, which blocks `:hover` and taps; it is now beside it)
- **v0.11.1** Populist Demands' skip (`vox/done`) is drawn in the declare hint (`declareHint` in `surfaces.ts` pairs each declare type with its decline)
- **v0.11.0** `hard` scores the pip menu with each action's sub-flow resolved (`settleSubflows`, gated as `exp:s1`: +6.3 pts win share per side, z 2.68 — docs/19 §26), and bots think in a worker on both the server (`worker_threads`, `bot-worker.js` beside `main.js`) and the page (a Web Worker), so a multi-second `hard` decision no longer stalls the server or freezes the tab. The week's other experiments (committed strategies, B2, engine speed, learned policy) were null and are written up in docs/19 §26 and `docs/spikes/`; their raw run data is in `runs/archive-2026-09.tar.xz`
- **v0.10.1** the phone map pans, pinches and zooms while you watch another turn (only the Board sits inside `Watching`'s `inert`, not MapZoom)
- **v0.10.0** Undo works online: `POST /games/:id/undo` takes back the seat's own last move while nobody has acted since and it revealed nothing (engine `takeBackBlock`: no dice/shuffle, no card from a deck, the undealt discard or a rival's hand, no Farseers look); watchers get a `reset` push; the Undo button disables itself with the reason. This replaces hand-editing the journal for most misclicks
